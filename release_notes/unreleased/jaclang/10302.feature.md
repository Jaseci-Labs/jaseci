- **`jac studio`**: a compiler-backed terminal workspace for working on a Jac codebase with coding agents. The project is loaded into a graph of packages, modules, archetypes, abilities and impls joined by the archwire wiring, with users, uses and walker traversals linked; the navigator and the wiring view (providers, consumers, rules, and the violations a wire causes) browse it, and the code view adds semantic highlighting, hover, definitions, references, diagnostics and inferred types. Select modules, symbols and wires into a context tray and hand them to any ACP agent (Claude Code, Codex, Gemini CLI, your own) or the built-in byLLM agent, each started with `jac mcp` and the studio's own MCP tools (`studio_selection`, `studio_focus`, `studio_link_plan`, ...). Every file an agent writes is held while the compiler checks it: the approval sheet shows the verdict, per-symbol changes, new diagnostics and architecture changes, lets you accept part of an edit symbol by symbol, sends the findings back on rejection, and requires a separate approval for wiring changes. Sessions persist on a root graph and can be resumed and forked; `jac studio model`, `ask`, `agents` and `sessions` work without the UI. See the [Jac Studio reference](../../reference/studio.md). Osprey, the Jac TUI framework the studio is built on, now lives in the repository at `jac/jaclang/osprey`.
