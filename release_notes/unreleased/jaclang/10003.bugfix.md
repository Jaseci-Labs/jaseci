- **Fix: more than one serve worker on a stock external Postgres no longer turns requests into 500s**: concurrent SERIALIZABLE request transactions could run Postgres's predicate-lock table out (`53200 out of shared memory`), and when the failing statement was a typed hop the request failed outright. A request that hits a transient database error (serialization failure, deadlock, lock timeout, `53200` or a dropped connection) is now re-run like a write conflict, up to `conflict_max_attempts`. On an external Postgres whose `max_pred_locks_per_transaction` pool is smaller than the one jac gives its own Postgres, the server also logs a warning at startup naming the setting and the value to use.
