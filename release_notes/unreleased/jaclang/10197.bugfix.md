- **Fix: native kernel builds spend less time outside lowering**: lowering a virtual call, a dispatched field or a class constant no longer scans every class's resolution order to find the classes deriving from a type; the layout registry answers from an index it builds once.
- **Fix: a warm native kernel build lowers each stale unit once**: the build checks a cached unit against the interfaces its dependencies have now, before any consumer reads it, so a compiler change no longer leaves stale units to be adopted and rebuilt in rounds afterwards. A unit is stale only when a direct dependency's interface changed, so a stale dependency that lowers to the same interface does not rebuild everything above it.
- **Fix: sealing links the compiler kernel from its units' objects**: the seal no longer merges the kernel into one module, optimizes it whole-program and emits it on one thread; it links each unit's optimized object, the way `jac native build kernel` does. The whole-program kernel compiled no faster and cost about 800 s of a 2,160 s CI seal.
- **Fix: whole-program native links generate code in parallel**: a `bitcode` link splits its optimized program into one partition per emit job and generates each in its own process, as many at a time as available memory holds, instead of emitting one object on one thread. Parallel unit optimization and emission also run in processes rather than threads, which contended on the shared address space, and the kernel link releases the analyzed trees before code generation.
