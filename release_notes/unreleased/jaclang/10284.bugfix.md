- **A dev checkout reports its real version**: `jac --version` and everything keyed on it (the docs version label, serve manifests) read the version from the nearest `jaclang` manifest above the source tree, which now lives in the repo-root `jac.toml`. A 0.38.0 checkout used to report the stale 0.16.7 from leftover package metadata.
- **A swallowed read-only retry no longer commits half an attempt**: a unit's first write on a read-only snapshot raises `ReadOnlyRetry` so the server re-runs it at SERIALIZABLE, but a broad `except Exception` in user code (a scheduled sync, for one) swallowed it, the attempt carried on over the rolled-back transaction, and writes after the swallow were committed alone. The session now refuses every later write in that unit with the same retry (nested walks commit inside the unit, so a write could otherwise land before the unit ends) and raises it again at the unit's exit, so the server still re-runs the unit and nothing from the swallowed attempt is kept.
- **Docs nav parsing reads any docs tree**: `guide_store.nav_manifest()` and `nav_pages()` take an optional `docs_root`, so a docs tree other than the bundled one (an older release's docs exported from a checkout) parses the same way. Existing callers are unchanged.
- **`JacTestClient` serves the same module a real server does**: it initialized the prepared application and then served the entry module under its plain name, loading a second copy of every module. Nodes fetched with `jobj()` were instances of the other copy's classes, so `isinstance` checks failed and lookup-by-id walkers silently did nothing under test while working when served. The client now serves the module the application initialized, and its `reload()` passes the entry file to the hot reloader (`build_services().hot_reloader` takes an optional `entry_path`).
- **A colocated service app's `@schedule` targets run under `jac run`**: colocated services were registered only for bridged calls, so their static schedules never reached the scheduler and a service's scheduled job ran only in a fleet. The serving process now registers the static schedules each colocated service declares, keyed `<app>.<name>` so claims stay per service.
- **A wire chained to two functions of one module reaches both**: `P ++> m.f | m.g { name }` kept one scope per wire and module, so `g` silently got no import, and since `jac fmt` merges same-payload consumers into one chain, formatting alone could break working wiring. Every scope a wire names in a module now gets its import.
- **`jac guide --section` takes a unique prefix**: guides point readers at sections by short names ("read **Effects**"), but only an exact slug or title matched, so `--section effects` failed against `effects-dependency-arrays-cleanup-and-the-entryexit-closure-split`. A unique slug or title prefix now selects the section, and an ambiguous one lists the candidates.
