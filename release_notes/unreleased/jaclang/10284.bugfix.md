- **A dev checkout reports its real version**: `jac --version` and everything keyed on it (the docs version label, serve manifests) read the version from the nearest `jaclang` manifest above the source tree, which now lives in the repo-root `jac.toml`. A 0.38.0 checkout used to report the stale 0.16.7 from leftover package metadata.
- **A swallowed read-only retry no longer commits half an attempt**: a unit's first write on a read-only snapshot raises `ReadOnlyRetry` so the server re-runs it at SERIALIZABLE, but a broad `except Exception` in user code (a scheduled sync, for one) swallowed it, the attempt carried on over the rolled-back transaction, and writes after the swallow were committed alone. The session now refuses every later write in that unit with the same retry (nested walks commit inside the unit, so a write could otherwise land before the unit ends) and raises it again at the unit's exit, so the server still re-runs the unit and nothing from the swallowed attempt is kept.
- **Docs nav parsing reads any docs tree**: `guide_store.nav_manifest()` and `nav_pages()` take an optional `docs_root`, so a docs tree other than the bundled one (an older release's docs exported from a checkout) parses the same way. Existing callers are unchanged.
- **`JacTestClient` serves the same module a real server does**: it initialized the prepared application and then served the entry module under its plain name, loading a second copy of every module. Nodes fetched with `jobj()` were instances of the other copy's classes, so `isinstance` checks failed and lookup-by-id walkers silently did nothing under test while working when served. The client now serves the module the application initialized, and its `reload()` passes the entry file to the hot reloader (`build_services().hot_reloader` takes an optional `entry_path`).
- **A colocated service app's `@schedule` targets run under `jac run`**: colocated services were registered only for bridged calls, so their static schedules never reached the scheduler and a service's scheduled job ran only in a fleet. The serving process now registers the static schedules each colocated service declares, keyed `<app>.<name>` so claims stay per service.
- **A wire chained to two functions of one module reaches both**: `P ++> m.f | m.g { name }` kept one scope per wire and module, so `g` silently got no import, and since `jac fmt` merges same-payload consumers into one chain, formatting alone could break working wiring. Every scope a wire names in a module now gets its import.
- **`jac guide --section` takes a unique prefix**: guides point readers at sections by short names ("read **Effects**"), but only an exact slug or title matched, so `--section effects` failed against `effects-dependency-arrays-cleanup-and-the-entryexit-closure-split`. A unique slug or title prefix now selects the section, and an ambiguous one lists the candidates.
- **byLLM typed returns work on models that reject forced tool choice**: litellm implements `response_format` on such providers as a forced tool call, which some models (newer Anthropic models among them) refuse with `tool_choice ... not supported`, so every typed `by llm()` call failed. byLLM now repeats the call once without the forced output (the schema hint stays in the prompt and the reply is still validated and retried), downgrades a forced `tool_choice` to `auto`, and remembers the model so later calls skip the rejected attempt.
- **`bind_na_host` checks no longer flip on warm caches**: when the native module was read as an interface only, the export's symbol did not lead back to its ability and `jac check` reported E5110 ("Host binding requires statically known export and host types") on some runs and not others. The check now follows the export through its import, and through the consumer's import of that name, to the provider module's tree.
- **Scheduled functions keep firing after a hot reload**: a scheduled target declared outside the entry module is found through the served surface, but each tick looked it up only in the introspector's cache and the entry module's attributes. A reload cleared the cache, so under `jac run --dev` every tick failed with "'<name>' is no longer registered" until a restart. A tick now resolves its target through the served surface when the cache misses.
- **`jac browse fill` replaces the field on macOS**: `fill` cleared the field with Ctrl+A before typing, but headless Chromium on macOS does not turn key combos into editing commands, so nothing was selected and the new text was added to the old value. `fill` now uses the platform's select-all shortcut, and on macOS Cmd+A, C, X, V and Z (and Cmd+Shift+Z) carry the matching Chromium editing command, so `jac browse press Meta+a` selects all there too.
- **`jac run --dev` serves the configured page head**: the dev server's `index.html` took only the `scripts` key from `[client.app_meta_data]` and otherwise used a fixed head, so every app showed the title "Jac App (Dev)", had none of its meta tags, and 404'd on `/favicon.ico` because the configured icon was never linked. The dev head is now built by the same `HeaderBuilder` a production page uses, with " (Dev)" added to the title.
- **A block-bodied lambda sees the narrowing of what it captures**: inside `if b is not None { f = lambda -> int { return b.n; }; }` the checker reported `b` as possibly `None` (E1099), while the same body as a nested `def` passed, because a lambda's statements were never linked into the flow at its definition site. They now are, like a nested function's.
- **`jac run --dev` recovers once a broken shared module is fixed**: in a workspace with colocated services, a type error saved into a module a service imports was recorded in that service's compilation context, and a hot reload dropped the module's errors only from the main app's context. After the file was fixed, the service's next compile was blocked by the leftover errors, so every reload and request kept failing with the old diagnostics (repeated once per failed attempt, at lines the file no longer had) until the server restarted. A reload now drops an edited module's errors from every app context it invalidates.
- **A retried prepare no longer passes over a module that failed**: a failed prepare left its analysed modules in the program, the broken one marked fresh with its errors already on record. A retry with no edit (another `jac run --dev` reload, a dynamic import) reused that module without reporting its errors again, so the server compile passed over it, and in a web app a broken client component then surfaced only as a client build error, or not at all when no client bundle was built. A prepare now first analyses again every module an earlier compile left with errors, along with the modules that import it, so the retry fails with the module's current errors (once, not stacked on the earlier attempt's).
- **A client build error shows the failed module's own errors**: `ClientBundleBuilder` read the errors of a failed compile from the root program, but the compile records them in the app's own compilation context, so it saw none and printed every error the root program held, often only an unrelated module's errors and never the failed module's. It now reads the program that compiled the module, and when the errors were recorded by an earlier compile it shows only those in the module and the modules it imports.
- **`jacSignup` solves the registration challenge**: with `[serve.auth.registration] challenge = true` the server refuses a registration without a solved proof-of-work challenge, and `jacSignup` never fetched one, so every app with challenges on had to hand-roll registration. When the auth policy says a challenge is required, `jacSignup` now fetches it from `POST /user/register/challenge`, solves it, and sends the proof with the registration, in the browser and in React Native alike (the runtime hashes with its own SHA-256, so it needs no `crypto.subtle`). A challenge that cannot be fetched, has no solution, or expires first comes back as the `SignupResult` error, and the registration is not sent.
- **A colocated service schedules functions it imports**: colocated schedule discovery kept only targets defined in the service's entry module, so a service that imported a scheduled `tick` from `tasks.jac` ran it in a fleet but never under `jac run`. Colocated services now take their schedules from the same source a standalone service uses (the schedules in the service's namespace plus the scheduled targets of its served surface), read through the same introspector their colocated endpoints use.
- **Null-safe trailers keep their null safety in client code**: the JavaScript backend ignored the null-safe flag on `?.` and `?[...]`, so `details.error?.message` compiled to `details.error.message` and reading through a missing value threw a `TypeError` instead of yielding `undefined`. Attribute reads, calls, slices and literal indexes now emit JavaScript optional chains (`?.`), and the reads lowered to runtime helpers (non-literal indexes, `str`/`list` methods, polymorphic method calls) are guarded so a nullish receiver short-circuits to `undefined`, with the receiver evaluated once. An assignment target keeps plain `.`, since JavaScript rejects an optional chain there.
- **Native loops over non-ASCII strings are linear again**: since native strings index and count codepoints, every `s[i]`, `s[a:b]`, `len(s)` and `s.find(x, start)` on a string holding any non-ASCII character converted between codepoints and bytes by scanning from the first byte, so an ordinary `while i < len(s)` loop over such a string was quadratic (40,000 characters took about 2 s instead of 1 ms), and the native compiler slowed several-fold on sources containing characters like `·`. Each thread now keeps a small cursor for each long non-ASCII string it reads, so indexing, slicing, `len` and searching walk from the last position (forward or backward) instead of from the start. A string's cursor is dropped before its memory is freed, so a new string allocated at the same address never inherits it.
