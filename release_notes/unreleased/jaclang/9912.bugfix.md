- **Fix: byLLM names union and generic return types as written in errors and retry prompts**: when a typed `by` call's reply could not be converted, the conversion error, the `finish_tool` validation error and the retry prompt sent to the model took the return type's name from `__name__`, so `int | None` appeared as `Union`, and the non-conforming-value error showed a plain `int` as `<class 'int'>`. They now name the type as written (`int | None`, `list[Person]`, `tuple[int, ...]`), and the conversion and `finish_tool` errors chain the underlying JSON or validation error as their `__cause__`. On a Python older than the bundled 3.14 (for example through `python -m jaclang`), a union return also raised `AttributeError: 'types.UnionType' object has no attribute '__name__'` in place of `OutputConversionError`, so typed-output retries never ran; it now fails and retries like any other typed return.
