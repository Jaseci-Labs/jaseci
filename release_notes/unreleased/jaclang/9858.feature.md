- **js_engine: a Node.js-compatible JavaScript engine written in Jac, an accelerator over bun**: `jac/js_engine/` holds the engine. `jac native build js-engine` (the `zig build js-engine` step) links it with the in-repo compiler into `libjs_engine.so`, beside `libjs_native.so` (its C shims, PCRE2, libuv, nghttp2, llhttp, brotli and ICU, compiled by Zig from `build.zig.zon` pins), the pinned Wasmtime C API and the precompiled builtins, and installs that `js/` directory for every jac. Whenever an engine is built and current, jac runs JavaScript on it: the `jac` binary invoked as `node` (the engine's `bin/node` link) runs it in-process, which is how Vite, the cl test runner, `jac x` and npm scripts execute, and `jac install --npm` and the client build's dependency sync call its package manager in-process. Releases ship bun, its floor, and nothing builds the engine implicitly. CI builds and gates it (the node suite, a client build, test262 against its baseline) on pull requests labeled `native:js-engine` and nightly. A Jac shared library whose root module has an entry now exports it as `jac_main(argc, argv)`, `jac build --native --lib` exports only the root module's `:pub` surface (its imports' `:pub` symbols stay internal, so the whole-program optimizer treats them like an executable's), and the native linker's static-archive floor selects members across archives, so a library that needs another (libssl needing libcrypto) links.
