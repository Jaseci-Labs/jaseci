- **Fix: native lists with the same contents compare equal whatever their element storage**: List equality only compared two lists of one native list type; any other pair fell through to comparing the list pointers, so `list(struct.unpack("<3H", data)) == [1, 2, 3]` (tagged values against plain ints) and a `list[int]` against a `list[float]` were always unequal, with no diagnostic. `==` and `!=` now compare such lists by length and then element by element. An int against a float is compared exactly, so `[9007199254740993] == [9007199254740992.0]` is False as in Python; a `bytearray`, which shares its storage with a list of bytes, is never equal to a list; and an element a typed list keeps as a bare pointer (a nested list, a dict, an object, a string) is compared as the kind its checked type names, so one object held by a typed list and by a list of `any` equals itself.
