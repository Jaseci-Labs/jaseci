- **Serve: a request that loses a write conflict waits its turn instead of racing again**: when a request is re-run because another writer changed a node it was writing, the session now queues on that node (a Postgres advisory lock, so the order holds across workers and replicas) and opens its re-run by locking the node's row, so newer requests cannot commit it in between. Concurrent writers to one node now drain in order instead of colliding until their attempts run out and the client gets 409. Requests that never conflict take no extra locks.
