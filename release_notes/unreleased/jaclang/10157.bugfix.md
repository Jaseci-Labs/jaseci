- **Fix: the native kernel exports `jc_analyze` and `jc_compile` again**: since #10108 a native kernel lost both entry points. Code #10108 added to the compile path could not be lowered (placement decoding over `any`, `jac_dependencies` on an `any` receiver, the stub catalog writer, the endpoint effect pass's callable summaries), and the demotions reached the entry points. `jac run` then stopped with "the loaded kernel has no jc_compile", and `jac check` silently ran on the bytecode compiler. That code is now lowerable, or sits behind the host asker. `jac native build kernel` (and the build-kit seal) now refuses a kernel that would not export an entry point its loader calls, naming each one and the chain of demotions that removed it. `jac check` stops with a clear error when the loaded kernel lacks `jc_analyze`, instead of falling back. A native kernel does not yet record the unit interfaces an edit prepare reuses, so on it those modules are analysed again.
