- **Data: the Postgres wire client reads through a buffer and caches its SQL rewrite**: protocol messages are now sliced out of a per-connection read buffer filled in 64 KiB reads, instead of two `recv` calls per message, so a result of N rows no longer costs 2N syscalls. Notifications that arrive in the same read as ReadyForQuery are queued on the connection, so a `select()`-driven LISTEN loop never waits on bytes the client already holds. The named-to-positional parameter rewrite is cached per SQL text.
