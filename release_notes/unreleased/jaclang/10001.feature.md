- **One artifact router: every native and on-demand artifact resolves the same way, and nothing builds implicitly**: the compiler kernel, stub catalog, LLVM shim, C/musl/wasm floors, precompiled bundle, LLVM C backend, bun, JacPython, the embedded Postgres distribution, and the managed Node/JDK/patchelf tools are entries in one registry. Each resolves to its built or provisioned copy when one is current, and otherwise to its floor (bytecode, source parsing, Python placement) with one loud notice naming the fix. jac's own artifacts are built only by `jac native build [names] [--force] [--exact]`; `jac native status [names]` shows what each one resolved to and what moved. Toolchains and Postgres for your app are still provisioned on first use, with one notice, and a project that sets `[network] offline = true` refuses instead of downloading.
  **Breaking change**: the artifact environment variables are gone. `JAC_OFFLINE=1` is now `[network] offline = true` in `jac.toml`; `JAC_TOOLCHAIN_USE_SYSTEM=0` is `[toolchains] system = false`; `JAC_TOOLCHAIN_DIR` is gone (toolchains live under the cache root, `JAC_CACHE_HOME`); `JAC_PG_DIST` / `JAC_PG_VERSION` are `[database] postgres_dist` / `postgres_version` (a fetched distribution in the cache is found without either); `JAC_SCALE_BINARY_PATH` is `[dev] pod_binary`; `JAC_NO_DEV_SOURCE` is gone (start jac outside any `[dev]` project to run its bundled compiler); `jac kernel` is `jac native`. Building JacPython is a build option, `zig build -Dpython=jacpython`.
