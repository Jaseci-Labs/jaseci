- **Fix: commits after a served response no longer re-serialize every loaded list or dict holder**: a request commits on spawn completion, at its response, at unit exit and on close, and each commit re-hashed every loaded anchor holding a `list`, `dict`, `set` or object to catch in-place changes. After the response commit no user code runs before the next unit, so the server now seals the scan there and the later commits flush only changed and deleted rows; entering a unit, aborting, `on_commit` callbacks and pending effects unseal it.
