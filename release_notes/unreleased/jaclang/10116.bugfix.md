- **Fix: commits after a served response no longer re-serialize every loaded list or dict holder**: a request commits on spawn completion, at its response, at unit exit and on close, and each commit re-hashed every loaded anchor holding a `list`, `dict`, `set` or object to catch in-place changes. When the response is plain data (primitives, lists and dicts of them), no user code runs after the response commit, so the server now seals the scan there and the later commits flush only changed and deleted rows; entering a unit, aborting, `on_commit` callbacks and pending effects unseal it.
