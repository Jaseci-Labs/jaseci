- **Fix: a promise read through an awaited null-safe guard stays a promise in client code**: `recv(x)?[await key()]` (and a call with `**kwargs` whose arguments await) waited on whatever the guarded expression produced, so a stored `Promise` came back as its resolved value and calling `.then()` on it failed. The value is now handed back unchanged.
- **Fix: `**` on an untyped operand is a power in client code**: `a ** 2` with `a: any` compiled to `a + 2`. It now compiles to JavaScript's `**`. `a // b` on untyped operands compiled to `a + b` and now floors the quotient, and `a //= b` (on any operand type) compiled to `a = b` and now assigns the floored quotient.
- **Fix: `(await f()) ** n` compiles to valid JavaScript**: the parentheses around an awaited or negated base were dropped, producing `await f() ** n`, which JavaScript rejects. The base of `**` keeps its parentheses.
- **Fix: a client call with keywords to a target the compiler cannot resolve keeps its positional arguments**: `x.f(1, **kw)` with `x: any` compiled to `x.f({...kw})`. Positional arguments are now passed in order, followed by the keyword object (`x.f(1, {...kw})`), and `**` sources are evaluated once.
- **Fix: a call or trailer after a null-safe subscript short-circuits with it in client code**: `x?[k](n)` threw on a missing `x` instead of producing `undefined`. As in a JavaScript optional chain, a missing value now skips the rest of the chain (calls, attribute reads, subscripts), including after a null-safe method call such as `s?.strip().upper()`. Parentheses end the chain, and an assignment through one (`x?[k].a = v`) still assigns.
