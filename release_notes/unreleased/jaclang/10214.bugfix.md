- **Fix: a declaration and its `impl` are one element**: a body in an `impl` (same file, sibling annex or `impl/` folder) now behaves exactly like the same body written inline. An impl'd client component is placed with its declaration instead of compiling to an empty server function (`E5005`), a lambda that rebinds a local or a component's `has` state inside an impl body compiles (no more "no binding for nonlocal"), and an archetype whose methods are impl'd is pulled to the client like its inline twin, so browser globals such as `Math` type-check in it. Under the hood the compiler asks every body-relative question (the enclosing function, the owning archetype, the codespace, the scope a name binds in, the placement element) through the declaration: an impl's scope folds into its declaration's when they are matched, placement never treats a linked impl as an element of its own, and the Python and JavaScript backends lower an impl body only at its declaration. `separate-impls` (W3055) now also moves client component bodies into impls.
