- **Fix: a function with no return annotation returns None under native**: native used to compile a function or method written without `-> T` to return the integer `0`, so `v = f(); v is None` was False and `if result is None` guards never fired. Method calls also turned a `-> None` result into `0`. These callables now return None like on the server. A plain `f();` call stays native. Using the result as a value (`v = f()`, `str(f())`, `if f()`, ...) moves only the calling function to the server, where it gets `None`, instead of failing the whole module with an LLVM parse error (E5020). Calls across the native/Python bridge also pass None correctly: a void native function called from Python no longer returns a garbage integer, and a Python callback returning None no longer raises a ctypes `TypeError`.
