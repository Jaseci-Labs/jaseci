- **Fix: native lowering cost scales with the unit, not with its import closure**: lowering one unit of a native build used to analyze every module its imports reach, transitively, and paid a near-constant few seconds per unit plus long collector pauses as the session's heap grew. Dependency discovery now follows a unit's own imports, analyzes nothing, and runs before any IR is built; a unit reads the interfaces of every dependency its imports reach before it emits code, and a dependency that declares nothing native is never analyzed. An importer declares an imported function only when it first names it, and a function body reads the names around it through one lexical scope instead of copying them. Each unit's IR crosses into LLVM once, moves between LLVM contexts as bitcode, and is released as soon as LLVM holds it. The native-only check reads the fallbacks the lowering recorded instead of rescanning printed IR. The build session holds the compile-time collector thresholds and freezes what it keeps at each unit boundary. A kernel module first reached by the native import walk is now placed as a native unit instead of by inference, which had turned a tolerated demotion into a failed kernel build. `jac native build kernel --stop-after N` times an uncached kernel build up to its Nth lowered unit and reports the phase split, collector pauses, peak memory, failures and per-unit lowering time.
