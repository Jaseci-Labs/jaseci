- **Breaking: `jac start` serves with as many workers as fit when `[serve.workers] count` is unset**: the default used to be one worker process. An unset count now starts one worker per core of the CPU quota, no more than available memory allows at 512 MiB per worker, and falls back to one worker (logging why) when more would be refused: `--dev` hot reload, a memory WebSocket backplane, `[scale.events]` without a database, or a cluster without a signing secret. An explicit `count` behaves as before. Apps that keep state in module globals (in-memory caches, counters) now get one copy per worker; set `count = "1"` to keep a single process. In-process `serve_background` stays single-process, and `jac scale deploy` keeps one worker per pod unless `count` is configured.
