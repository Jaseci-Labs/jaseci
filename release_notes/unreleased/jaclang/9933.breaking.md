- **Breaking: a closure created in a loop body keeps its own iteration's values**: a name whose every assignment is inside a loop (the loop target, or a local the loop body introduces, annotated or not) is now shared between a `lambda` or nested `def` created in the loop body and the rest of the function only while that pass lasts; when the pass ends the closure keeps the value it saw. Every per-item handler built in a JSX `for` slot acts on its own item, and a list of callbacks built in a loop on the server reads each iteration's values, in every codespace. A comprehension's variables are bound per element the same way. A name also assigned outside the loop is shared as before. This replaces the unreleased `E2097`/`W2084` diagnostics (#9902), which are removed. In client code a `for` target read after its loop is now a function local, so reading it no longer throws.
