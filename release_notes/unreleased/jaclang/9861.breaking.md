- **Placement is one judgment, made after a module is typed, per element**: a module with no declared codespace that could prefer native used to be stamped native by a guess before it was type-checked, and one that could not have it was analyzed again for the server with the verdict stored for the next compile. Such a module is now typed first with no codespace assumed. What only native code can do (a native-only builtin, a function address held as an `int`) is recorded as a requirement, and what native code lacks (a native capability, a native standard-library member, a finding that only matters natively) as a refusal. The placement pass reads those facts and places each top-level element: native unless something refuses it, and a call between elements placed apart is allowed when the callee's signature can cross that boundary. So one function that cannot be native no longer takes its module with it. Every module is analyzed once: the tree placement decides is the tree both backends read, and the native backend binds interface declarations to the native library. A refusal only the native backend can see places the module on the server in place, before the Python backend emits it, instead of compiling it again; a native unit the host cannot link after the kernel lowered it is an error instead of a silent second compile. Whether a module may prefer native is no longer decided by a syntactic scan at parse: what refuses native is read off the typed module, an element at a time (an async or `by llm` ability, inline Python, an endpoint, an import with no native form and the code that uses it), with persistent-graph access still refusing the module, and an import closure is judged from each dependency's own placement summary rather than by parsing it again. A native pin or a native project kind is now a preference placed the same way, so an element that cannot be native stays in Python instead of sending its whole module to the server; a module with a declared codespace (a forced or ahead-of-time build, the native library, a native unit) is typed once in that codespace as before, and client placement is inferred before typing as before. The native verdict is gone: nothing about placement is remembered between compiles beyond each module's summary. **Breaking:** a function or walker a client calls must have a signature that can cross as a request; a type with no wire form (a callable, a file handle, a dict with non-`str` keys, a generator parameter) is `E5115`. Native standard-library modules must conform to the Python interface of the same name, and each platform variant must expose the same public surface (`E5114`). Public names, parameters and members the interface does not declare were renamed or made internal (for example `calendar.calendar(theyear, ...)`, `os.path.getsize(filename)`, `locale.localize(string, ...)`; `gettext.c2py_ast` and `plural_index` give way to `gettext.c2py`; `urllib.request.urlopen` returns an `http.client.HTTPResponse` read with `read()` and `getheader()`), so native code that named them must use the Python spelling. A native-only builtin (`File`, `BinaryFile`) used in code that cannot be placed native is `E5090`.
